# BrainScanAI 2.0 - Advanced Project Upgrade Plan

## 1. Project Goal

Transform the old **Brain Tumor Detection Using CNN** college project into a modern, interview-ready, end-to-end medical imaging AI system.

The upgraded project should demonstrate more than image classification. It should show practical skills across:

- Computer Vision
- Deep Learning
- Transfer Learning
- Explainable AI
- Segmentation
- Uncertainty Estimation
- Medical Image Processing
- FastAPI
- Modern frontend development
- Databases
- MLOps
- Testing
- Docker
- CI/CD
- Deployment
- Responsible AI
- Optional GenAI integration

The final system should be positioned as an **AI-assisted MRI analysis and research prototype**, not as a clinically approved diagnostic system.

---

# 2. Current Project Baseline

The existing project already contains:

- Flask web application
- MRI image upload
- TensorFlow / Keras CNN models
- Tumor vs no-tumor detection
- Four-class tumor classification:
  - Glioma
  - Meningioma
  - Pituitary
  - No Tumor
- Confidence score
- Grad-CAM-style visualization
- Confusion matrix
- ROC curve
- Classification report
- Training and testing scripts
- Around 7,023 MRI images

This is a useful baseline, but several architectural and scientific issues must be fixed before adding advanced features.

# 3. Problems That Must Be Fixed First

## 3.1 Redundant two-stage classification

Current architecture:

```text
MRI
 |
 v
Tumor / No Tumor Model
 |
 v
Glioma / Meningioma / Pituitary / No Tumor Model
```

This is inconsistent because the second model already includes the `No Tumor` class.

### New approach

Use one clean four-class classifier:

```text
MRI
 |
 v
Classifier
 |
 +-- Glioma
 +-- Meningioma
 +-- Pituitary
 +-- No Tumor
```

A separate detector should only be introduced later if there is a strong experimental reason for it.

---

## 3.2 Binary training logic

The current training code appears to use a four-folder dataset with binary classification.

This must be removed or redesigned.

The new pipeline should explicitly define:

```text
class_to_idx:
0 = glioma
1 = meningioma
2 = pituitary
3 = no_tumor
```

Every experiment must save this class mapping.

---

## 3.3 Incorrect Grad-CAM implementation

The current Grad-CAM is generated from a different MobileNetV2 model instead of the actual classifier used for prediction.

This makes the explanation scientifically invalid.

### Required fix

Grad-CAM must use:

```text
Actual prediction model
        |
        v
Last convolution layer
        |
        v
Gradient computation
        |
        v
Class-specific heatmap
```

Later we can support:

- Grad-CAM
- Grad-CAM++
- Integrated Gradients

---

## 3.4 Unsupported accuracy claims

Do not display claims such as:

```text
98.7% accuracy
```

unless that exact result comes from a reproducible experiment.

All displayed metrics must come from evaluation artifacts generated by the current model version.

---

## 3.5 Security and engineering cleanup

Fix:

- hardcoded absolute paths
- `debug=True` in production
- insecure uploaded filenames
- sample uploads stored permanently
- missing configuration management
- missing requirements
- missing README
- missing tests
- tracked `__pycache__`
- research/debug scripts left in production code

# 12. Data Leakage Checks

Before trusting accuracy:

1. Calculate perceptual hashes.
2. Look for duplicate and near-duplicate images.
3. Check duplicates between train and test.
4. Verify split methodology.
5. Avoid augmentation before dataset splitting.
6. Ensure images from the same original subject do not cross splits when subject identifiers are available.

A suspiciously high result must be investigated rather than advertised.

Codex should NOT attempt to rewrite the entire project in one request.

For every phase:

1. Inspect existing implementation.
2. Explain what will change.
3. Identify affected files.
4. Implement one bounded task.
5. Run tests.
6. Run the relevant application or script.
7. Report errors.
8. Fix errors.
9. Update documentation.
